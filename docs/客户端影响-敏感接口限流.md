# 客户端影响：敏感接口限流（账户维度 + IP 维度）

> 适用版本：classing-backend ≥ 2026-07-12
> 影响端：Android Mobile / Android Wear / Web Admin（兑换、简报测试、官方云写入、密码修改、邮箱变更、APK 下载流程）

## 变更原因

此前仅 `/api/v1/auth/*` 认证接口有 IP 维度限流（20 次/分钟/IP），公告与版本查询有公共客户端限流（3 次/分钟/IP+路径）。但兑换、简报测试、官方云写入、密码修改、邮箱变更确认等敏感写接口**无任何限流**，攻击者持有有效 access token 后可高频调用进行兑换码爆破、邮件轰炸或云文档打满。此外所有限流器仅有 IP 维度，攻击者通过 IP 轮换（代理池 / 设备农场）即可绕过。

本次在敏感写接口上叠加**账户维度**限流（键为 `user:<userId>`，IP 轮换无法绕过）与共享 **IP 维度**限流，并将公开下载接口纳入公共客户端限流。

## 限流策略

### 敏感写接口

所有敏感写接口共享一个 IP 维度限流器，并按风险分级挂载各自的账户维度限流器：

| 接口 | IP 维度（共享） | 账户维度 | 超限错误码 |
|---|---|---|---|
| `POST /api/v1/membership/redeem` | 60 次/分钟 | 10 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `POST /api/v1/briefings/daily/test` | 60 次/分钟 | 5 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `PUT /api/v1/cloud/official/document` | 60 次/分钟 | 30 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `PUT /api/v1/briefings/daily` | 60 次/分钟 | 30 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `DELETE /api/v1/briefings/daily` | 60 次/分钟 | 30 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `PATCH /api/v1/account/me` | 60 次/分钟 | 10 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `PUT /api/v1/account/password` | 60 次/分钟 | 10 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |
| `POST /api/v1/account/email/confirm` | 60 次/分钟 | 10 次/分钟 | `IP_RATE_LIMITED` / `ACCOUNT_RATE_LIMITED` |

IP 维度先于账户维度校验；IP 维度超限时直接返回 `IP_RATE_LIMITED`，不消耗账户配额。

### 公开下载接口

| 接口 | 限制 | 超限错误码 |
|---|---|---|
| `GET /api/v1/client/releases/{id}/download` | 3 次/分钟/IP+路径 | `CLIENT_RATE_LIMITED` |

与公告查询（`GET /api/v1/client/announcements`）和最新版本查询（`GET /api/v1/client/releases/latest`）共享限流策略。限流键为 `IP + 路径`，不同 releaseId 的下载各自独立计 3 次/分钟。

## 429 响应格式

所有 429 响应均携带 `Retry-After: 60` 响应头（单位：秒），响应体遵循统一错误格式：

```json
{
  "code": "ACCOUNT_RATE_LIMITED",
  "message": "too many requests from this account",
  "requestId": "req_..."
}
```

| HTTP | code | 触发场景 | Retry-After |
|---|---|---|---|
| 429 | `IP_RATE_LIMITED` | 同一 IP 对敏感接口的请求超过 60 次/分钟 | 60 |
| 429 | `ACCOUNT_RATE_LIMITED` | 同一账户对某类敏感接口的请求超过该接口的账户配额 | 60 |
| 429 | `CLIENT_RATE_LIMITED` | 公开接口（公告/版本/下载）超过 3 次/分钟/IP+路径 | 60 |

## 客户端适配要点

### 通用 429 处理

- 客户端**不应**在收到 429 后立即重试，应读取 `Retry-After` 响应头并按该值（秒）退避。
- 建议对 429 采用指数退避 + 抖动，避免退避窗口结束后多客户端同时重试。
- 429 响应**不应**视为致命错误，UI 应展示「请求过于频繁，请稍后重试」而非崩溃或退出登录。

### 兑换（`POST /api/v1/membership/redeem`）

- 10 次/分钟/账户。正常用户不会触及，但批量重试无效兑换码会触发。
- 收到 `ACCOUNT_RATE_LIMITED` 时禁用兑换按钮 60 秒，展示倒计时。
- 兑换失败（`MEMBERSHIP_REDEEM_*` 错误码）不应自动重试。

### 简报测试（`POST /api/v1/briefings/daily/test`）

- 5 次/分钟/账户，是所有敏感接口中最严格的。
- 测试按钮点击后应进入冷却（60 秒禁用），避免用户连续点击触发邮件轰炸。
- `EMAIL` / `BOTH` 渠道会创建真实邮件任务，更应避免高频调用。

### 官方云写入（`PUT /api/v1/cloud/official/document`）

- 30 次/分钟/账户。正常同步频率（≤ `EVERY_15_MIN`）远低于此限制。
- 若客户端因并发冲突（409/412）自动重试，应限制重试次数 ≤ 3 并带退避，避免在短时间内打满配额。

### 密码修改与邮箱变更（`PUT /account/password`、`PATCH /account/me`、`POST /account/email/confirm`）

- 10 次/分钟/账户。
- 邮箱变更另有 60 秒重发冷却（`429 ACCOUNT_EMAIL_RATE_LIMITED`），与本次账户维度限流独立：前者是同一邮箱变更请求的重发间隔，后者是对该接口的总调用次数。两者可能先后触发。
- 邮箱变更确认（`POST /account/email/confirm`）错误输入累计 10 次后锁定 challenge（`400 ACCOUNT_EMAIL_VERIFICATION_INVALID`），与账户维度限流的 10 次/分钟独立计数。

### APK 下载（`GET /client/releases/{id}/download`）

- 3 次/分钟/IP+路径。不同 releaseId 各自独立。
- 下载失败重试应指数退避（建议 30s → 60s → 120s），**不应**在 1 分钟内重试超过 3 次。
- 客户端已有本地 3 次/分钟保护（公告/版本查询），下载路径应纳入同一保护逻辑。
- `Range` 请求恢复下载与限流计数共享预算；大文件分段下载不会被该限流阻断（同一请求只计一次），但连续发起多个分段请求会消耗配额。

## 与既有限流的关系

本次限流与既有策略叠加，不替换：

| 既有策略 | 接口 | 本次变更 |
|---|---|---|
| IP 限流 20 次/分钟 | `/api/v1/auth/*` | 不变 |
| 公共限流 3 次/分钟/IP+路径 | 公告、最新版本查询 | **新增**下载接口 |
| 登录失败 5 次/15 分钟 | `POST /auth/login` | 不变 |
| 验证码 10 次错误锁定 | 注册/邮箱变更/密码重置 | 不变 |
| 邮箱重发冷却 60 秒 | `PATCH /account/me` | 不变（与账户维度独立） |
| **IP 维度 60 次/分钟** | 敏感写接口（见上表） | **新增** |
| **账户维度 5–30 次/分钟** | 敏感写接口（见上表） | **新增** |
