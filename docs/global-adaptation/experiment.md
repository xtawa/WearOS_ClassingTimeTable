# 一周“零维护课表”实验与报告模板

状态：未招募、未分组、未运行。样本量0，结论待填写。不能根据本地合成测试推断留存、付费意愿或维护负担。

主假设：导入核对后，一周内用户更少手动修改，同时下一节课保持正确；付费提示不会挡住基础建表。先招募12–20人做导入，另至少5人做3秒查课；10个LMS访谈可重叠，但分别报告分母。小样本只用于发现失败和决定下一轮，不作为显著商业结论。

A：首次流程完全完成后，在用户主动进入官方云/AI时展示功能说明。B：建表成功页出现可关闭的功能介绍；不自动开购买页、不阻止继续查课、相同免费边界和价格。当前没有生产A/B开关或付费入口，这里是待执行实验方案；测试原型可由研究员呈现两种提示，不修改真实权益。

研究员预先随机分组、记录分配序列；竞品对照使用相同合成课表并随机展示顺序。首次完成后观察7天，参与者自愿开启本地指标；关闭即可删除本机记录。导出JSON只在本地指标面板汇总，分组由研究员单独的匿名ID表保存，App不采集组别/个人信息。

指标与口径：

- 建表完成率：有明确creation session的实际保存完成 / 开始；缺开关同意的会话不进入采集，报告自选择偏差。
- 耗时：进入首启到实际保存的elapsedRealtime；只统计有正耗时的成功会话，另列未完成数。
- 纠错：同一已完成creation session的逐项编辑次数；未完成会话修正另报，不混入均值。
- D7：首次开始日+7 UTC日的ACTIVE_DAY；尚未满7天的安装不进分母；关指标/换机可能丢样本，注明限制。
- 同步失败率：实际配置完整并发起的同步失败 / 尝试；没有配置、排队不计失败或applied。
- 零维护：第1–7天人工维护次数 / 人；自动处理调课数 / 应处理调课数；Next正确回答 / 抽样核对次数。后三项需人工观察记录，现有匿名事件不足以直接估算。
