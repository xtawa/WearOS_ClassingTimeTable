# 验收步骤与记录模板

当前只有代码、本地自动测试和合成样例；下表的执行结果均待实测填写。建议指标来自 Todoist，不能当成本轮结果。

## 导入与人工纠错

`fixtures/` 有5张PNG、5份PDF、人工标注JSON与manifest，均为合成排课。包含常规周、AB周、Lecture/Lab、冲突、缺结束时间；未知时间必须保留警告，不补造课时。

逐份操作：新安装→可选指标开关→导入→检查整表草稿→故意修改一节课→查看冲突→取消核对原课表未变→重新导入并确认→Today/Next/Wear核对。ICS另外运行自动15组展开用例，并与系统日历导入同文件对比；月/年/ordinal规则等不支持项必须有警告，不能静默近似。图片最长2048px、JPEG约2.5MB上限；PDF1–5页逐页请求；多页失败不提交已识别的部分。自然语言使用现有课程提案合同（单次最多20个动作），输出必须经过同一草稿编辑器。

招募12–20人，随机分配ICS/截图/PDF/手工，尽量每组3–5人。开始时间为看到首启界面，完成为正确显示预先标注的下一节课；不能以点击“完成”替代核对成功。记录取消、异常、人工修正与放弃位置。目标≥80%在120秒内完成，逐课核对漏/重/时地错误；样本小需报告原始人数和区间，不宣称总体准确率。

记录 [usability.csv](templates/usability.csv)。课堂内容用案例编号，参与者用匿名ID；不收密码、截图中个人身份信息或课程原文。

## Next / Widget / Watch

至少5名目标用户在3秒内回答课程、开始时间、教室、还有多久；对照同一排课数据与随机顺序的竞品界面。检查未建表、已创建空表、今日无课、待上课、课中、课间、放学，查下一课不能越过学期末。

手机Widget：小/中尺寸、light/dark、长名称、最小尺寸、改教室/删课/新增课、跨开始/结束边界、重启、时区切换、离线超过24小时。倒计时采用RemoteViews Chronometer；WorkManager边界任务是尽力刷新，Doze/厂商后台限制可能延迟，不宣称准点秒级换课。[官方Widget更新约束](https://developer.android.com/develop/ui/views/appwidgets/advanced)要求合理后台调度。

Wear：圆/方屏不同尺寸，Tile两行长课名、时间/教室，黑底白字；已有Complication短/长格式需检查表盘主题、AOD、空数据和课程切换。截屏保存到本机材料目录，不把浏览器预览视作AOD证据。Apple Watch仅设计规划，没有可运行iOS工程。

## 每类20轮跨设备一致性

前置：匹配market/package的手机和Wear；记录版本、匿名node ID、Wi-Fi/Bluetooth条件与统一时钟。每轮保存初始课表摘要、操作、终态节数/ID摘要、入队时间和applied ACK时间；事件不记录token。

| 场景 | 步骤 | 成功判定 |
|---|---|---|
| 有课/0节/远程删除 | 云上建2课→全量→删1→增量→全删→空全量 | 三端课程/例外ID和版本一致，0节是显式空表 |
| 官方云对象/数组payload | 分别用V2对象及V1数组；加入malformed域 | 正常映射；异常报错，不清成0节 |
| 断网编辑重连 | 手机上改房间、删课，Wear离线→重连 | 旧课不复活；queued不显示applied |
| ACK先到/迟到/乱序 | 延迟传输，重复ACK，错node，过期请求 | 基线仅匹配请求/节点/revision且applied时推进 |
| 多表/重装/换机 | 两个Wear节点；清缓存后请求全量；手机换机恢复 | 节点基线不混用，多节点使用全量；重置后强制全量；无幽灵课 |
| 云冲突/恢复 | 两客户端分别改同课，CAS冲突、重试、备份恢复 | 按版本合同合并；删除不误覆盖新版本 |
| 取消/调课/补课 | 窗口外调入/调出、取消+移动、复杂规则 | 手机/Wear/后端日期与数量一致 |
| DST/时区/重启 | NY spring/fall；Shanghai↔NY；系统重启 | 校历基准一致，提醒不重复；旅行策略需单独核对 |

目标最终一致性100%；在线applied延迟P95<30秒是待测目标。按场景分组，20轮用排序第19个值作为nearest-rank P95；并给最大值与失败数，不能用平均值替代P95。记录 [reliability.csv](templates/reliability.csv)。

时区限制：ICS按导入选定zone展开成具体日期与当地时间；跨DST的源TZID已做自动用例。当前课表存储没有稳定的“源学校时区+旅行显示时区”双时区模型，设备跨区后保持本地wall-clock语义；跨区不偏移的整套体验未完成，验收不得勾选已通过。重启/时区广播重建提醒与Widget已接入；实际重复提醒/后台刷新须实机核对。

## LMS 与购买

访谈至少10名真实Canvas/Moodle用户：学校类型、是否给开发者key、管理员是否允许服务、最常用course/assignment/calendar字段、作业与节次差别、token可撤销性、期望回退。不要向参与者索取密码或token。用 [lms-interviews.csv](templates/lms-interviews.csv) 记录匿名需求，不声称访谈已发生。

获学校/用户授权后，至少3套脱敏数据分别包含普通课程、多课程/分页、撤销权限与无日期作业。只读调用校验字段来源、去重、时区、权限失败回退；将临时token只保存在设备输入框。购买/恢复另依 [release.md](release.md) 使用Play内部测试完成，不能以mock付款或Release构建替代。

ICS的DST处理依据 [RFC 5545 recurrence](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.3.10)：重复生成的不存在时刻跳过且不计COUNT；DTEND定义的精确持续时间跨DST保持长度。具体日期的显式DTSTART按其时区解释，与生成的重复实例分开处理。
